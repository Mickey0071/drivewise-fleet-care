
- Export branding: all .xlsx/.pdf reports use src/lib/branding.ts (logo from src/assets/camauto-logo-base64.ts, colors, company block) via branded-xlsx.ts / branded-pdf.ts; CSV stays raw. Why: one source so report styling never drifts.
- Vehicle spare-key status uses the shared VehicleSpareKey control and vehicles.spare_key_made through the vehicle store, with saved-row verification. Why: fleet cards and vehicle details must show the same durable status.
- Individual vehicle analytics PDFs receive the visible tab's financial and average-expense values and reuse shared branding and expense grouping. Why: printed totals and breakdowns must match the selected car without independent calculations.
- Service history includes direct vehicle expenses via service-history-expenses, excluding tolls and expenses whose linked repair is already reported. Why: direct entry needs no repair workflow and must not duplicate completed service costs.
- Additional-driver files (license, selfie, signature, addendum) are stored as private rental-signing bucket paths and signed on demand (short TTL); packet merges use src/lib/additional-drivers.server.ts. Why: IDs must never have long-lived public links.
- Rental agreement PDF renderers use a continuous vector layout and the shared one-page fitting helper; browser printing measures its compact template before print. Why: preserve full content and signatures without page breaks or clipping.
- Returning-renter agreement signing resolves eligibility through returning-renter.server.ts using the token-bound driver and rechecks on submission; returning-renter.ts owns the tested rules. Why: clients must never authorize reuse or supply prior document URLs.
- Repair close-out uses repair-closeout.ts for cost/balance rules and waits for cloudReady plus a saved-row read-back before success. Why: completed work must not erase ticket costs or imply payment.
- Rent-to-own uses rto_contracts/rto_payments with money rules in src/lib/rto.ts (tested); Stripe links carry kind=rto_payment and the webhook records them idempotently by session id. Why: balance math stays in one place and online payments never double-count.
- Public link access uses exact route-prefix boundaries in public-routes.ts, with token-authorized RTO signing separate from administration. Why: signature links require no account without exposing admin pages.
- Rent-to-own reservation views reuse the contract workspace and shared live print dialog. Why: payment actions and printed balances stay consistent across entry points.
- Reservations bind rent-to-own contracts by exact driver, vehicle and start date through findRtoForRental, displaying contract payoff and suppressing duplicate standalone rows without changing signature/approval status. Why: existing on-rent bookings must not treat contract down payments as prepaid rental credit.
